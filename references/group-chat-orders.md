# 群聊发货记录专项

发货类群聊（`群聊_发货群A.xlsx`、`群聊_发货群B.xlsx`）与私聊形态完全不同，
**不要套用私聊的解析逻辑**。

## 消息形态

一条消息里同时含设备、地址、收件人、电话：

```
发一套201A，(加瓶药水)。(1200)，顺丰到付。
云南省罗平县，罗平水泥厂路小张汽修。小张13800138001
```

```
发一套201A(1200)，
一套氮氧黑匣子(包含显示屏，一个扁五针氮氧传感器)。(956)
发货前测试一下氮氧传感器，录视频给我。
顺丰陆运到付。
内蒙古鄂尔多斯市伊金霍洛旗某镇某汽车城某商贸公司。周八13800138002
```

**这类数据恰好能补齐私聊里缺失的「省份 / 城市 / 购买设备 / 发货日期」**，是价值最高的来源。
实测某发货群 43 条记录里，收件人 41、省份 36、城市 35、设备 41 ——填充率极高。

## 群聊特有的五个坑

### 1. 发送者不止一个

群里有多名业务员（甲总、乙主管、丙老板、丁主管…）。
**判断客户身份不能按发送者过滤**，要按「消息里有没有地址 + 电话」。
（私聊里可以只取 `who == '我'`，群聊里不行。）

### 2. 引用消息会重复整条原文

`[引用 XXX：<原文>]` 会把地址再抄一遍，同一客户出现好几次。
→ 必须**按手机号去重、取最早日期、设备取并集**。

### 3. 设备与地址常常是两条消息

同一秒或相邻 1 分钟内，一条给地址、一条给设备。例如：

```
18:38:46  甲总  山西省忻州市某街某汽修厂13800138003李四
18:38:46  甲总  发那个旧的维修的泵，一个旧的好用的喷嘴，一个144抽拉式芯。(600)
```

→ 按「同发送者 + 时间邻近」配对，配对结果在备注里注明「设备取自相邻消息，待确认」。

### 4. 同一客户多次下单

同一手机号在不同日期反复出现（补发、返修、加单）。
→ 合并成一行，日期取最早，设备取并集，**备注列出全部下单日期**。

### 5. 追踪单号消息会混进来

`SF0213800138004`、`单号`、`百世` 这类不含地址的消息，正则扫号码时会误命中。
→ 地址关键词过滤：必须同时含 `省|市|区|县|镇|路|村|号` 才算记录。

## 不要用正则抽姓名和设备

实测结果：

| 原文 | 正则抽出 | 正确 |
|---|---|---|
| `山西省忻州市某街某汽修厂13800138005李四` | 东汽修厂 | 李四 |
| `河北省唐山市滦南县某路东某车场王五13800138006` | 场王五 | 王五 |
| `重庆市南川区…13800138007 赵六` | 顺丰代 | 赵六 |
| `浙江省杭州市余杭区…` | 城市「江省杭州市」 | 杭州市 |

**正确做法：三段式**

1. 脚本粗抽（号码可靠，姓名/设备不可靠）→ 打印全部原文，带日期和发送者
2. **人工逐条比对，写死成常量表**：

   ```python
   # (手机号, 收件人, 省份, 城市, 购买设备, 日期, 原文地址/备注)
   D = [
     ('13800138008','孙七','广东省','佛山市','144/DPF总成2个',date(2026,8,14),
      '佛山市高明区更合镇某汽修'),
   ]
   ```

3. 脚本只负责按常量表写入 + 回读校验

40 条约十几分钟，90 条约半小时。这是必要投入——**正则这条路实测调不通**。

## 城市正则会吃掉省份，也会被「自治州」带偏

两个实测踩到的坑：

```python
# ❌ 错 1：'浙江省杭州市余杭区' 会匹配到 '江省杭州市'
# ❌ 错 2：'西双版纳傣族自治州景洪市' 会匹配到 '治州景洪市'
CITY = re.compile(r'([\u4e00-\u9fff]{2,4}市)')
```

正确做法是**两步**——先剥掉省份子串，再把「XX自治州/地区/盟」整段摘掉，然后才开始找市：

```python
# 1) 剥掉省份子串
prov_m = re.search(PROV_FULL, text) or re.search(PROV_SHORT, text)
rest = text.replace(prov_m.group(1), '', 1) if prov_m else text

# 2) 摘掉自治州/地区/盟，否则 '自治州景洪市' 会被贪婪切成「治州景洪市」
rest = ZHOU.sub('', rest)

# 3) 取第一个「XX市」，并排除候选里混进行政区划字的情况
BAD_CITY_CHARS = ('省', '区', '县', '族', '治')   # 注意：「州」不能排除，杭州/苏州/泰州都含州
def first_city(text):
    for m in CITY.finditer(text):
        if any(ch in m.group(1)[:-1] for ch in BAD_CITY_CHARS):
            continue
        return m.group(1)
    return ''
```

> 排除项里为什么是「治」而不是「州」：`自治州景洪市` 里要挡的是「治」，而 `杭州市`「苏州市」「泰州市」里的「州」是城市名的正常组成部分，挡了会误伤。

省份正则要同时覆盖全称和简称：

```python
PROV_FULL  = r'((?:北京|天津|上海|重庆)市|[\u4e00-\u9fff]{2,3}省|内蒙古自治区|新疆维吾尔自治区|广西壮族自治区|宁夏回族自治区|西藏自治区)'
PROV_SHORT = r'(河北|山西|辽宁|吉林|黑龙江|江苏|浙江|安徽|福建|江西|山东|河南|湖北|湖南|广东|海南|四川|贵州|云南|陕西|甘肃|青海|台湾|内蒙古|广西|西藏|宁夏|新疆)'
# 自治州/地区/盟/州 也算城市层
ZHOU = re.compile(r'([\u4e00-\u9fff]{2,6}(?:自治州|地区|盟|州))')
```

省份抽出后要**统一规范成标准全称**：`云南` → `云南省`，`宁夏省` → `宁夏回族自治区`，
`新疆` → `新疆维吾尔自治区`。这样台账里同一列不会一会儿「浙江」一会儿「浙江省」。

## 设备列怎么整理

用户的原始写法带价格和物流，入表时：

- **去掉**物流词：`顺丰到付|顺丰陆运到付|顺丰包邮|顺心捷达包邮|京东到付|顺丰代收|包邮|到付|陆运|快递`
- **去掉**价格：`(1200)`、`（956元）` 这类括号数字
- **保留**数量与规格：`201A一套`、`药水两瓶`、`4.2米通用款（DPF+SCR）`
- 多个设备用「、」分隔
- 一条消息里超过 60 字的行当正文丢弃，避免把说明文字当设备

## 汇总视角

两类来源性质不同，**不要擅自合并**：

| 来源 | 性质 |
|---|---|
| 私聊（发给渠道/大咖的号码清单） | **冷号码池**，未转化 |
| 发货群（含地址电话设备的指令） | **成交客户** |

实测四张表 399 个去重号码中，冷池与成交客户几乎不重叠（只零星交叠几个）。
交叉比对只**报告**重叠，是否合并由用户决定。
