# 台账字段规格

## 工作簿结构

三个 sheet：

| Sheet | 角色 |
|---|---|
| `客户信息` | 主表（明细录入） |
| `填写概览` | 汇总，KPI 全部由公式从主表派生 |
| `填写说明` | 字段口径说明 |

## 主表 `客户信息` 的 10 列

| 列 | 字段名 | 类型 | 来源 | 说明 |
|---|---|---|---|---|
| A | 序号 | 序号 | 计算列 | 第 1 行表头，数据从第 2 行开始。A2：`=IF($B2="","",ROW()-1)`，填充至第 1000 行 |
| B | 客户昵称 | 文本 | 聊天记录 | 微信昵称 / 收件人姓名 / 店名，用于认人 |
| C | 手机号 | 文本 | 聊天记录、发货记录 | **强制文本格式 `@`**。多个号码写同一格，用「、」分隔 |
| D | 微信号 | 文本 | 聊天记录 | **强制文本格式 `@`** |
| E | 聊天日期 | 日期 | 聊天记录 | `yyyy-mm-dd`；同一客户取最早一次出现 |
| F | 发货日期 | 日期 | 发货记录 | `yyyy-mm-dd`；多次发货取最早或最近，按用户口径 |
| G | 省份 | 文本 | 聊天记录、发货记录 | 只填原文写出的，不按城市反推 |
| H | 城市 | 文本 | 同上 | 原文没写「市」就留空 |
| I | 购买设备 | 文本 | 聊天记录 | 多台写一格，用「、」分隔，数量用「×N」或沿用原文「一套/两瓶」 |
| J | 备注 | 文本 | 推断 | 原文地址、待确认点、来源。列宽 40 字符，自动换行 |

## 样式与可用性

- 表头：商务蓝 `#4472C4` 底 + 白字 + 加粗 + 居中 + 下边框 thin，行高 26
- 数据区 A2:J1000：垂直顶端对齐；C/D/G/H/I/J 文本格式 `@`；E/F 日期格式 `yyyy-mm-dd`
- 条件格式（范围 C2:D1000，公式 `=AND($B2<>"",$C2="",$D2="")`）：黄底 `#FFEB9C` + 深黄字 `#9C6500`
  —— 提示「有客户但手机号和微信号都空」
- 冻结 `A2`；筛选 `A1:J1000`

## `填写概览` 的 KPI

第 1 行合并标题（A1:B1）；第 2 行表头；第 3 行起指标：

```excel
客户总数      =COUNTA(客户信息!$B$2:$B$1000)
手机号已填    =SUMPRODUCT(--(客户信息!$C$2:$C$1000<>""))
微信号已填    =SUMPRODUCT(--(客户信息!$D$2:$D$1000<>""))
手机号缺失    =$B$3-$B$4
微信号缺失    =$B$3-$B$5
聊天日期已填  =SUMPRODUCT(--(客户信息!$E$2:$E$1000<>""))
发货日期已填  =SUMPRODUCT(--(客户信息!$F$2:$F$1000<>""))
省份已填      =SUMPRODUCT(--(客户信息!$G$2:$G$1000<>""))
城市已填      =SUMPRODUCT(--(客户信息!$H$2:$H$1000<>""))
设备已填      =SUMPRODUCT(--(客户信息!$I$2:$I$1000<>""))
```

用 `SUMPRODUCT(--(range<>""))` 而非 `COUNTIF(range,"?*")`——后者不统计数值型单元格。

## 地区口径

| 情况 | 省份列 | 城市列 | 备注列 |
|---|---|---|---|
| 原文「广东省深圳市南山区」 | 广东省 | 深圳市 | 原文地址 |
| 原文「浙江省乐清市城南街道」（县级市） | 浙江省 | 乐清市 | 原文地址 |
| 原文「河南省滑县长途汽车院内」 | 河南省 | 空 | 原文地址 + 「原文未写地级市」 |
| 原文「西安市灞桥区」（省份没写） | **空** | 西安市 | 原文地址 + 「原文未写省份」 |
| 直辖市「重庆市武隆区」 | 重庆市 | 空 | 原文地址 + 「直辖市，城市列留空」 |

**铁律**：用户选了「不补」就绝不按城市反推省份。这条是用户明确要求的。

- 省份写法规范化：`宁夏省` → `宁夏回族自治区`，`云南` → `云南省`，`新疆` → `新疆维吾尔自治区`，
  `内蒙古` → `内蒙古自治区`，`广西` → `广西壮族自治区`。规范化后在备注写明原文。
- 城市取原文中**第一个**「XX市」；没有「市」字的（`安徽淮南`、`防城港`）城市留空。

## 异常值与命名惯例

| 情况 | 处理 |
|---|---|
| 号码位数不对（10 位 / 12 位） | 照收 + 备注「仅 N 位，非 11 位手机号，待核对」 |
| 同一客户给了两个号码 | 同一格，用「、」分隔，备注注明 |
| 收件人只写姓（`叶`、`崔先生`、`郭`） | 照写，备注注明 |
| 原文无姓名、只有店名 | 店名填进昵称列，备注注明「原文无个人姓名，填店名」 |
| 原文无姓名也无店名 | 昵称留空，备注注明 |
| 原文自相矛盾（正文写 10 位、引用写 11 位） | 取更合理的那个，备注写清两种写法 |
| 同一账号多次下单 | 合并成一行，日期取最早，设备取并集，备注列出全部下单日期 |
| 原文含座机（`057188888888`） | 不入手机号列，备注写「另留座机 XXX（未入表）」 |
| 报价 / 金额 | **用户没要求就不入表**。要入也先问 |

## 备注列建议写法

统一用「原文地址：<完整地址>」开头，后面用「；」追加待确认项。示例：

```
原文地址：重庆市武隆区某洗车场张三收；直辖市，武隆区未拆入城市列；王老板转介绍
原文地址：西安市灞桥区某路某小区；原文未写省份
原文地址：浙江省乐清市城南街道某村；原文号码为12位，疑多打一位，待核对
```

这样任何一行都能回溯到聊天原文，用户核对成本最低。
